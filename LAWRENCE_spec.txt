0. How to read this document
This is the complete brief for Lawrence Private Collection: a portal listing exceptional property from roughly €20 million, built as a
normal, fully public, fully indexable listings site, with one addition — an Oﬀ-Market section that requires a free account.
There is deliberately no NDA, no proof of funds and no manual vetting in this phase. A visitor creates an account, conﬁrms
their email, and the oﬀ-market listings open. That is the whole gate. Everything heavier (NDA signature, ﬁnancial capability
conﬁrmation, per-member watermarking, manual approval) is designed for but not built — §23 speciﬁes exactly how each is switched
on later without a migration or a rewrite.
The same applies to the multi-agency backoﬃce: the data model carries the agency ﬁelds from day one, but Phase 1 runs as a singleteam CMS. Turning on external agency accounts is a conﬁguration and UI task, not an architectural one (§9.4).
It is written for one senior full-stack developer working with Cursor + Claude, and designed so the developer reaches 90–100 % of a
launch-ready site without asking the client a single question. Copy (§12), design values (§10.2), workﬂows (§8, §9), where
every piece of content comes from (§13) and 48 product decisions (§21) are all pre-answered.

# LAWRENCE PRIVATE COLLECTION — project rules for AI assistants
## What this is
A portal for trophy property from ~€20M. Two layers: a fully public, indexable Collection, and an
Off-Market section that requires a free member account (email confirmation only — no NDA, no
proof of funds, no manual vetting in this phase).
Next.js 15 App Router + Payload 3 + Postgres/PostGIS + Typesense, deployed on Vercel.
## Non-negotiable rules
1. Off-market content never leaks. It is never statically generated, never edge-cached, always
noindex, never in a sitemap, OG image, RSS feed, public API response or 404 suggestion list,
and always behind a server-side session check. Hiding it with CSS or a client-side conditional
is a bug, not an implementation.
2. Every data-layer function takes an explicit Viewer argument. There is no ambient current-user
global. A function that forgets the viewer must not compile.
3. Field visibility is decided by an ALLOWLIST projection per audience, never a denylist. A new
model field is invisible everywhere until someone adds it to a projection deliberately.
4. Public performance budgets are acceptance criteria: LCP < 1.2s mobile, first-load JS < 110KB
home / < 130KB listing gzip. Check `pnpm analyze` before committing.
5. No component or route queries the database directly; everything goes through /src/lib/db.
6. No hardcoded design values outside /src/tokens. No literal user-facing strings outside
/src/messages.
7. Controlled enums over free text, always.
8. Sample listings always carry isSample=true, show a SAMPLE badge, emit noindex and are excluded
from sitemaps.
9. WCAG 2.2 AA everywhere, including the account area.
10. Agency multi-tenancy fields exist on every relevant collection from day one and every query is
written agency-aware, even though Phase 1 runs single-team. Never remove them "for simplicity".
## Definition of done for any task
pnpm typecheck && pnpm lint && pnpm test && pnpm test:e2e && pnpm analyze pass;
new logic has tests; `pnpm audit:exposure` passes; no console or hydration errors.
## audit:exposure
A required script that crawls every public route as an anonymous visitor and asserts that no
response contains: an off-market listing id or slug, an exact address, owner data, internalValueEur,
or a price for a listing whose priceDisclosure is not "exact". Must pass before every merge.

3. Benchmarks
3.0 Legal boundary
We replicate interaction patterns and information architecture — conventions, not property. We never copy HTML/CSS/JS, scraped
markup, photography, logos, licensed fonts, listing copy, editorial text or a competitor's inventory. Scraping a competitor's database is
a terms breach and a legal risk, and is unnecessary (§13).

3.3 The thesis
At this price level the inventory is fragmented across brokerage websites that are slow, badly structured and invisible to search.
Nobody has built a fast, editorially serious, data-rich portal at the top of the market with a genuine research library in front of it. The
moat is twofold: the research content, which compounds and is what assistants cite, and the member base, which is an owned
audience rather than rented traﬃc.

4. Design decisions (settled — do not re-open)
1. Silence over spectacle. Fewer elements per screen than any competitor. One idea per viewport. No badges, no ribbons, no "hot
property", no countdown, no urgency devices.
2. Monochrome plus one warm metal. Obsidian, bone, graphite, with a muted aged-brass accent at ≤2 % of surface area (§10.2).
No gold gradients, no black-and-gold cliché.
3. Editorial typography. High-contrast serif display, quiet grotesque body, letterspaced small-caps labels, tabular ﬁgures for
every price and measurement.
4. Photography full-bleed, one uniform colour treatment, generous margins, never more than three images competing for
attention.
5. The Oﬀ-Market invitation is a whisper, not a wall. On public pages it appears as a single quiet line with a count ("41
properties are held oﬀ-market"), never as a blur, a lock icon or an interstitial.
6. Account creation is two ﬁelds. Email and password, or a magic link. Nothing else on that screen.
7. Slower motion. 300–420 ms, no parallax, no scroll-jacking, prefers-reduced-motion honoured.
8. Locality-level maps on public listings, exact pins only where the seller permits ( coordinatePrecision ); oﬀ-market listings always
show a circle, never a pin.
9. No live chat widget, ever. The desk is an enquiry form and a scheduled call.
10. Empty states are computed, never generic: name the most restrictive ﬁlter and oﬀer one click to relax it.

5.5 Market page grammar (the SEO engine)
Canonical: /[locale]/markets/[market] and /[locale]/markets/[market]/[segment] , where segment belongs to a controlled taxonomy:
waterfront-estates · vineyard-estates · ski-chalets · penthouses · private-islands · historic-estates · equestrian-estates · newdevelopments · golf-estates .

Rules: one canonical URL per combination; a resolver normalises aliases with
301s; slugs come from the Taxonomy collection, localised per locale; a page renders
only when it has published editorial copy plus at least three sourced data
points. Empty combinations are never auto-published — that is the fastest
route to a Helpful-Content demotion.

(property.channel = 'public')
? status is publicly visible AND (isSample allowed by config)

OR (viewer.kind = 'agency' AND property.agency = viewer.agencyId)

8.5 The registration ﬂow (deliberately two minutes)
1. Join ( /join ) — email + password, or magic link. Optional: name, phone, country, what they are looking for. Marketing consent
checkbox, unticked, optional. Turnstile. Nothing else.
2. Conﬁrm email — one click. Account becomes active and the Oﬀ-Market section opens immediately.
3. (Optional, ﬂag-gated and oﬀ by default) MEMBER_REQUIRE_APPROVAL=true sends new accounts to pending with an admin queue and a
"we will conﬁrm within one business day" message.
4. First login experience — a short, quiet welcome panel: here is the Oﬀ-Market section, here is how to save a listing, here is how to
tell us what you are looking for.
5. Requirements proﬁle (optional, prompted after the third oﬀ-market view) — budget, markets, types, timeline. Feeds the match
email and the admin view.
6. Members may delete their account themselves; deletion anonymises MemberActivity and removes saved listings.
Copy throughout is in §12.3, and it never says "sign up" — it says "create an account to see the oﬀ-market collection".

8.6 Member media and documents
Member-only images and all documents live in the private bucket and are served through /api/secure/media/[token] and
/api/secure/document/[token] : an HMAC over (assetId, memberId, expiry, nonce) , 15-minute lifetime, nonce burned in Redis, session
re-checked server-side, Cache-Control: private, no-store , X-Robots-Tag: noindex, noimageindex . An unauthenticated request returns
404, not 403 — never conﬁrm that an asset exists.
No watermarking in Phase 1; the pipeline is speciﬁed in §23.3 and can be enabled per asset later.

8.7 Activity and what it is for
MemberActivity is written on oﬀ-market list views, detail views, document downloads, saves and enquiries. It powers three things that
matter commercially: the admin's view of demand per listing, the "eleven members viewed your property this week" line the desk
gives sellers, and the match notiﬁcations. It is not analytics for its own sake, and no third-party script ever sees it.

8.8 Matching (small, high-value)

/src/lib/match.ts scores active Requirement records against new listings (budget overlap, market, type, must-haves). When a new oﬀmarket listing is published, matching members with notifyByEmail receive one discreet email. Admins see a matching board. One page
and one function — deliberately isolated so it can become embedding-based later without touching anything else.

9.3 Listing freshness
120-day cycle. At T-14 the responsible editor gets a "conﬁrm these are still available" list with one-click conﬁrmation. On expiry:
removed from search and sitemap, public URL returns 410 Gone with a designed page suggesting the market page. Sold listings keep
a "sold" state for 90 days without a price, then noindex , then 301 to the market page. Stale inventory is the fastest way to lose
credibility at this level.

13.2.2 Selection rules (implemented as ﬁlters, not taste). Reject any image under 2000 px on the long edge, or carrying a

13.2.4 People imagery — a real rule. Never use a stock portrait of a real person as a ﬁctional agent. It puts an identiﬁable
individual in front of a business they have never heard of: a personality-rights and GDPR problem independent of the stock licence.
Use monogram avatars generated from initials in brand colours (a 20-line SVG component). Real photographs only for real, consenting
staﬀ.

13.7 Editorial copy — the writing brief and the AI workﬂow
The developer writes the editorial with AI assistance. This is a legitimate, high-quality workﬂow; unreviewed AI output is not.
Market page (400–450 words): a 40–60-word answer paragraph opening the page (what the market is, what the entry price is,
what you get) · one paragraph on character and who buys there · one paragraph of hard speciﬁcs with our own ﬁgures · one paragraph
on buying practicalities (structures, typical costs, timelines, seasonality) · closing line to the listings. Two question-form H2s. No
adjective that could apply to any market.
Journal article (800–1,000 words): answer-ﬁrst opening, three to ﬁve question-form H2s, one table or list of concrete ﬁgures, every
non-obvious claim sourced with a link and a date, a short "what this means for buyers" close.
Report (600-word summary + 8-page PDF): a ﬁnding, a method note, three to ﬁve charts from open data, a table by market, and
a short caveats section. Honest methodology beats impressive claims: state the sample, the source and the limits.
Four non-negotiable rules:
1. Never publish a statistic produced from memory. Every number comes from a named source with a URL and a date, or from our
own database aggregates.

2. Every external claim carries an inline source and asOfDate .
3. The developer reads every published sentence. Anything not veriﬁable in 30 seconds is deleted rather than softened.
4. No AI-generated text about law, tax or residency beyond stating that a rule exists and linking the oﬃcial source.
Article backlog for launch (pick 8): how oﬀ-market sales actually work at €20 M+ · buying through an SPV versus directly, and
when share transfer makes sense · residency and investment-visa status across Portugal, Greece, Italy, Spain and the UAE (facts +
oﬃcial links only) · what it costs to complete: taxes and fees by market · heritage and listed-building constraints in Italy and France ·
the real timeline of a €50 M transaction · why prime markets decouple from national indices · running costs of a large estate, itemised

15. SEO and AI discovery
15.1 The principle
The public Collection is genuinely open and complete, so it can rank like any strong portal. The research library is what earns authority
and citations. The account gate sits only in front of the oﬀ-market inventory and the report PDFs — never in front of content we want
indexed.

15.2 Foundations
Canonical on every page · hreﬂang for all 6 locales + x-default · sitemap index split by type (properties, markets, segments, reports,
journal, static), 50k URLs max per child, correct lastmod , excluding oﬀ-market, sample, expired and non-public content · robots.txt ·
designed 404 and 410 · one H1 per page · breadcrumbs everywhere · 6–10 contextual internal links per market page · image ﬁlenames
and alt text generated from structured data ( villa-saint-tropez-sea-view-01.avif , alt "Nine-bedroom villa with sea view in SaintTropez, Côte d'Azur").

15.3 A ﬁnite crawl surface
All indexable browse states are canonical paths under /collection/... and /markets/... . Query-string ﬁlters are noindex, follow
and never linked from navigation. Pagination beyond page 1 is noindex, follow with a canonical to page 1. /off-market/* and
/account/* are excluded by robots.txt , by X-Robots-Tag , and by authentication — three independent layers.

17. Security and privacy
17.1 Application security
Member sessions in HttpOnly , Secure , SameSite=Lax cookies with a 30-day remember-me and silent refresh; optional TOTP 2FA for
members, mandatory for staﬀ; rate limits on login (5/15 min), join (3/h/IP), enquiry (5/h), signed media (60/min/member), password

CI; Sentry with PII scrubbing and no request bodies captured on member routes.

17.2 Exposure integrity (the critical control)
Allowlist projections (§8.3) · audit:exposure in CI · Playwright tests fetching every public route anonymously and asserting the absence
of oﬀ-market markers · a test asserting that an anonymous request to an oﬀ-market id returns 404 (not 403 — never conﬁrm
existence) · a test asserting signed media URLs expire and are single-use · a test asserting internalValueEur and addressLine never
appear in any response body. Treat a failure here as a production incident, not a test failure.

17.3 Multi-tenancy (dormant but enforced)
Even in single-team Phase 1, every listing query is agency-aware and the tenant access function exists with tests. This is what makes
Track B a conﬁguration change rather than a refactor.

23. Deferred features — exactly how each one switches on
Nothing here is built now. Each is listed with the seam that already exists, so the work is additive.

23.1 Member vetting and approval
Seam: Member.status already supports pending ; MEMBER_REQUIRE_APPROVAL already gates the join ﬂow; /admin/members already lists
accounts. Work: an approval queue UI, two email templates, and turning the ﬂag on. Half a day.

23.2 NDA and ﬁnancial capability conﬁrmation
Seam: Member.ndaStatus , ndaSignedAt , capabilityStatus , capabilityBand , tier exist and are unused; /lib/services/ is the integration
boundary; the projection table already supports more than two audiences. Work: an e-signature integration (Dropbox Sign, DocuSign,
Yousign), a capability upload with private storage, an admin review screen, tier promotion, and a fourth column in the projection table.
If this is ever built, a DPIA becomes necessary and capability documents must be deleted on veriﬁcation, with only the outcome
retained — design it that way from the ﬁrst line. Roughly two weeks.

23.3 Per-member forensic watermarking
Seam: all member media already ﬂows through /api/secure/media/[token] with the member id in scope, and MemberActivity already
records every access. Work: a sharp composite for images and a pdf-lib overlay for documents carrying the member's name and a
token, cached per member-asset pair for 24 h, with the token recorded in the activity row. Two to three days, and it is what convinces
the most cautious sellers to place inventory.

23.4 Named per-listing access
Seam: canSee() is a single function, and the projection table is data, not code. Work: an AccessGrant collection, one clause in canSee ,
an admin action, and an expiry job. Two days.

23.5 Agency feeds
Seam: Property.sourceType and ImportJob exist; the import validation pipeline arrives with Track B. Work: per-agency tokens, a
documented inbound JSON schema, adapters for common formats, and a cron diﬀ report. Public channel only. About a week.

23.6 Semantic matching and AI search
Seam: /src/lib/match.ts is one isolated function; no embedding column exists yet, deliberately, because it is machine-generated and
a script can backﬁll it in one run. Work: enable pgvector , add the column, backﬁll, swap the scoring function. Two days.

23.7 CRM, messaging, data rooms, payments
Seam: /lib/services is empty and is the only place external integrations may attach; Enquiry and Document already model the data.
All are additive.
